# 长期维护说明

本文补充仓库级维护边界；用户可见的安装与更新步骤仍以 [README](../README.md)、[巨魔安装说明](INSTALL.zh-CN.md) 和 [App 内更新说明](SELF-UPDATE.md) 为准。

## 维护对象与版本边界

- 本仓库是加载现有库存网站的 iOS WKWebView 外壳工程；网站内容及其显示版本由网站侧独立发布。本仓库不是库存网站后端，不要将这里的 App 版本当作网页版本，也不要据此宣称其他后端已就绪。
- 工作流 [Build TrollStore IPA](../.github/workflows/build-ipa.yml) 采用手动 `workflow_dispatch`，其中 `APP_VERSION` 是工作流构建/Release 使用的 App 版本；维护 App 版本时，应使该值与 README 的安装版本、Release 文件名说明保持一致。发布后以实际 Release 附件及测试报告核对，不要把网页版本混入 App 版本。
- [AppConfig.swift](../SkincareInventory/AppConfig.swift) 包含固定网站 URL、受信主机、Release URL 和 App 版本回退值。更换固定站点时应一并核对 `websiteURL` 与 `trustedHost`，并单独确认 `releasesURL` 是否仍指向预期更新来源；不可只改 README 或只改其中一项。
- README 当前记录固定 Bundle ID `io.github.saimilai.skincareinventory`。若要更改 Bundle ID，应先核对 Xcode 工程中的实际设置，并对安装身份迁移作专项验证；在取得相应验证证据前，不要承诺既有安装或本地数据会无缝迁移。

## 文档同步

1. **App 版本或安装/更新行为变化：**同步 README、[巨魔安装说明](INSTALL.zh-CN.md) 与 [App 内更新说明](SELF-UPDATE.md) 中受影响的步骤、版本和文件名。只在实际流程改变时修改对应说明；不要复制历史验收记录来替代当前 Release 的测试报告。
2. **网站地址、受信主机或更新来源变化：**先核对 `AppConfig.swift` 中相关配置，再检查 README 对固定网站、联网使用和网页版本边界的描述；安装/更新文档只有在其步骤或行为受影响时才同步。不得把站点迁移描述成后端就绪或自动同步。
3. **Bundle ID 或其他安装身份变化：**核对实际工程配置、README 与受影响的安装/更新说明。只有取得对应验证证据后，才可更新有关既有安装、覆盖更新或数据延续的承诺。
4. 修改安装/更新文档前，先阅读待审阅提交中的实际内容，再按受影响的行为同步；不要仅凭文件路径或目录存在推断其内容。

## 验证与陈述边界

- 当前工作流由人工触发，包含自动脚本/模拟器检查和构建发布步骤。对文档变更本身，不应暗示已触发工作流、已生成新 Release 或完成实机验收。
- README 明确指出，自动检查和模拟器结果不等于真实 iPhone / TrollStore 验收；当前也未记录真实设备安装、启动、文件分享及覆盖更新后数据保留的验证。只有取得针对实际设备与版本的证据后，才能调整这些陈述。
- 保留 App 与 Safari 数据状态互不自动同步、网页重新加载需要网络等现有边界。除非相应实现和证据均有变化，不要将它们改写为自动同步或离线可用承诺。
- 本维护说明只约定文档随实际变化同步；不授权或要求变更业务行为、工作流触发方式、权限、安全、费用条件或发布/部署安排。
