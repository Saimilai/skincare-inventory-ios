# App 内覆盖更新

`库存 1.0.1` 首次提供 App 内的更新入口。`1.0.0` 用户需要先通过巨魔手动覆盖安装 `1.0.1`，之后才能使用这个入口。

## 更新流程

1. App 冷启动每天最多静默检查一次 GitHub 公共 Release；也可以在顶部“App 更新”中手动检查。检查不会刷新库存网页。
2. 你确认已保存录入内容并完成 JSON 备份后，App 下载 Release 中匹配版本的 IPA 和 `SHA256SUMS.txt`。下载大小、SHA-256、Release 来源、ZIP 结构、Bundle ID、版本和必需文件都会再次校验。
3. 如果设备上的 TrollStore 安装助手与本工程审查的官方 2.1.1 版本完全匹配，界面会显示“在 App 内覆盖更新”。你确认后，App 只调用固定的 `install <已校验IPA>` 命令，不打开巨魔界面，也不接受网页传入的路径、命令或参数。
4. 覆盖安装会结束旧的“库存”进程。安装完成后从桌面重新打开 App，核对顶部版本和库存；不要把旧界面没有自动返回当成安装失败或成功。
5. 如果助手版本、安装位置或权限无法精确确认，原生按钮会保持不可用，App 保留“通过巨魔文件交接更新”，把同一个已校验 IPA 交给系统“打开方式”。

## 数据与权限边界

覆盖更新沿用固定 Bundle ID `io.github.saimilai.skincareinventory`，并要求当前 App 仍位于 iOS 数据容器中；安装路径不使用 `no-container` 或 `container-required=false`。因此设计目标是保留当前 App 的 WKWebView 持久化库存，但同一容器保留、安装子进程在旧进程结束后继续完成等结果只能在真实巨魔设备上确认。请在更新前导出 JSON。卸载 App 不属于覆盖更新，可能删除本地库存。

App 使用少量私有运行权限来发现并调用固定的巨魔安装助手。权限清单没有把任意 root helper 或网页命令暴露给 WebView；网页桥接仍只处理本站主页面发起的 JSON/XLSX 文件操作。

## 官方版本核对

本工程固定核对 TrollStore 官方仓库提交 `88424f683b2a08f34a3f88985f790f97d84ce1df`（2.1.1）发布归档中的 `TrollStore.app/trollstorehelper`：大小 `4,086,819` 字节，SHA-256 `3634607f8165fb41c6844cb0b7608f38ee1f51c2e96e353ed13d4c76a28aa1bd`。官方 RootHelper 的 `install` 路径使用同 Bundle ID 覆盖 App；本工程只把这些公开证据用于精确匹配，不把任意同名文件当作可信安装器。设备上经过修改的巨魔安装可能无法匹配，遇到这种情况请使用系统文件交接。

## 测试边界

模拟器只验证不可用时的安全回退、持久化存储引用和更新入口，不执行 root 安装。自动化构建也不能证明真实设备上旧进程结束后 helper 子进程仍能完成，或覆盖后库存一定保留；这两项需要在你的巨魔设备上先备份 JSON，再用虚构记录实测。
